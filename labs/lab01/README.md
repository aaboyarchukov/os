# minibox

Упрощённый аналог [BusyBox](https://ru.wikipedia.org/wiki/BusyBox): один
исполняемый файл, внутри которого живут все команды. Читает команды со
стандартного потока ввода и выполняет операции с файлами.

Написан на C11, без внешних зависимостей. Собирается статически и запускается
в Docker-образе `FROM scratch`, где кроме самого бинарника нет ничего.

## Реализованная функциональность

| Команда                 | Описание                                     | Статус         |
| ----------------------- | -------------------------------------------- | -------------- |
| `echo ARG...`           | Вывести аргументы через пробел               | готово         |
| `cat FILE...`           | Вывести содержимое файлов (включая бинарные) | готово         |
| `cp SOURCE DESTINATION` | Скопировать файл, сохранив права доступа     | готово         |
| `cd PATH`               | Сменить текущий каталог                      | готово         |
| `ls [PATH]`             | Список всех файлов каталога, включая скрытые | готово         |
| `mkdir PATH`            | Создать каталог                              | готово         |
| `rm [-r] PATH`          | Удалить файл или каталог рекурсивно          | в разработке   |
| `stat PATH`             | Размер, тип, число ссылок, права файла       | в разработке   |
| `mount` / `umount`      | Подключение образов дисков                   | не реализовано |

Вложенные конструкции SHELL (`for`, `if`, конвейеры, перенаправления,
кавычки) не поддерживаются — по условию задания они не требуются.

### Поведение

Интерпретатор читает строки до конца потока ввода (EOF, `Ctrl-D`).
Пустые строки пропускаются. Неизвестная команда не прерывает работу.

Сообщения об ошибках идут **только в стандартный поток ошибок**, результат
работы команд — в стандартный поток вывода. Потоки можно разделить:

```
$ printf 'cat nope.txt\necho ok\n' | ./minibox 2>/dev/null
ok
$ printf 'cat nope.txt\necho ok\n' | ./minibox 2>&1 >/dev/null
cat: nope.txt: No such file or directory
```

Максимальное число аргументов в строке — 64 (`MAX_ARGS` в `tokenizer.h`).
При превышении команда не выполняется, выводится сообщение об ошибке.

## Быстрый старт

### Docker (основной способ)

```bash
docker build -t minibox .
```

Сборка не требует ничего, кроме Docker: стадия `build` сама поднимает
временный контейнер, вызывает в нём `make` и уничтожается.

**Интерактивный запуск** — основной способ работы:

```bash
docker run -it --rm minibox
```

`-i` держит стандартный ввод открытым, `-t` выделяет терминал. Дальше
команды набираются обычным образом, по одной на строку. Выход — `Ctrl-D`.

```
echo привет
привет
mkdir data
ls
.
..
data
```

Чтобы работать с файлами хоста, смонтируй каталог томом — внутри образа
`FROM scratch` своих файлов нет:

```bash
docker run -it --rm -v "$PWD:/w" minibox
```

```
cat /w/README.md
cp /w/README.md /w/copy.md
ls /w
```

**Неинтерактивный запуск** (скрипты, CI) — без `-t`:

```bash
printf 'echo привет\nls /\n' | docker run -i --rm minibox
docker run -i --rm -v "$PWD:/w" minibox < script.txt
```

Флаг `-i` обязателен и здесь: без него стандартный ввод закрыт, и
интерпретатор завершится сразу по EOF.

Итоговый образ — около 1 МБ и содержит ровно один файл.

### Локальная сборка

Нужны `gcc` (или `clang`) и `make`. Под Linux:

```bash
make                 # собрать ./minibox
make check-static    # убедиться, что бинарник статический
make test            # прогнать тесты токенизатора
make clean           # удалить артефакты сборки

./minibox            # интерактивно
./minibox < script.txt
```

Под macOS сборка `-static` не поддерживается (Apple не позволяет статически
линковать libSystem), а Linux-специфичные вызовы отсутствуют. Для разработки
можно собрать без `-static`:

```bash
clang -std=c11 -D_POSIX_C_SOURCE=200809L -Wall -Wextra -Wpedantic \
      main.c dispatcher.c cmds.c consts.c tokenizer.c -o minibox
```

Финальный артефакт в любом случае собирается в Docker.

## Структура проекта

```
main.c          цикл REPL: чтение строки → разбор → вызов команды
tokenizer.c/.h  разбиение строки на argc/argv
dispatcher.c/.h таблица команд, поиск обработчика по имени
cmds.c/.h       реализации команд
consts.c/.h     строковые имена команд
tokenizer_test.c тесты токенизатора
Makefile        сборка, тесты, проверка статической линковки
Dockerfile      многостадийная сборка образа FROM scratch
```

### Как это работает

1. `getline` читает строку со стандартного ввода, перевод строки срезается.
2. `tokenize` разбивает строку **на месте**: разделители заменяются на `'\0'`,
   в массив складываются указатели внутрь того же буфера. Копирования нет.
3. `convert_to_enum` переводит имя команды в значение перечисления.
4. `get_cmd` ищет обработчик в таблице команд; для неизвестного имени
   возвращает заглушку, печатающую ошибку.
5. Обработчик вызывается с привычной сигнатурой `(int argc, char **argv)`,
   где `argv[0]` — имя самой команды.

Работа с файлами ведётся через системные вызовы `open`/`read`/`write`, а не
через `FILE*`: это обязательно для корректного копирования бинарных файлов,
в которых встречаются нулевые байты.

## Требования к сборке

Проект собирается с `-std=c11` и макросом `-D_POSIX_C_SOURCE=200809L`.
Макрос обязателен: со строгим режимом ISO C библиотека glibc не объявляет
POSIX-функции (`getline`, `lstat`, `ssize_t`, `PATH_MAX`), и сборка падает.

Код компилируется без предупреждений при
`-Wall -Wextra -Wpedantic -Wshadow -Wconversion`.

## Проверка

```bash
# санитайзеры (без -static, только для отладки)
gcc -std=c11 -D_POSIX_C_SOURCE=200809L -Wall -Wextra \
    -fsanitize=address,undefined -g \
    main.c dispatcher.c cmds.c consts.c tokenizer.c -o minibox-asan

# поиск утечек
valgrind --leak-check=full ./minibox < script.txt
```
