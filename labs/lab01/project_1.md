# Проект minibox

Необходимо реализовать упрощенный аналог командного интерпретатора [BusyBox](https://ru.wikipedia.org/wiki/BusyBox), который реализован в виде ровно одного исполняемого файла и реализует базовые операции работы с файлами.


## Обязательные требования

 - Проект необходимо реализовать на Си или C++
 - Исполняемый файл не должен иметь зависимостей, и должен уметь запускаться в образе Docker `FROM scratch` после копирования только одного файла в образ.

Командный интерпретатор читает со стандартного потока ввода строки команд
и выполняет определенный десйствия. Реализовывать полноценную поддержку
вложенных конструкций языка SHELL (такие как `for`, `if` и прочие) **не требуется**.

В процессе выполнения команд могут возникать ошибки, которые необходимо 
обрабатывать, и выводить подробные сообщения в отдельный поток ошибок, а
не в стандартный поток вывода.


## Ожидаемые артефакты выполения проекта

Для допуска к защите проекта необходимо создать Git-репозиторий, в котором 
небходимо разместить:
 1. Полный набор исходных текстов реализации проекта
 2. Файл README.md в корне проекта с кратким описанием реализованной 
 функциональности и инструкцией по использованию
 3. Файл `Dockerfile` с раздельными стадиями для воспроизводимой
 сборки образа с приложением
 4. При использовании сборщиков проектов (`make`, `cmake` и пр.) - файлы
 с описанием проекта; при этом вызов инструментов для сборки должен проиходить
 из сборки Docker-образа.



## Функциональные требования на оценку "удовлетворительно"

Реализованы команды:
  1. `echo ARG...` - вывести текст аргументов на стандартный поток вывода
  2. `cat FILE...` - вывести содержимое указанных файлов 
  3. `cp SOURCE DESTINATION` - скопировать содержимое файла в новый файл; файлы могут быть как текстовыми, так и бинарными


## Функциональные требования на оценку "хорошо"

Дополнительно к критериям на оценку "удовлетворительно", реализованы команды:
  1. `cd PATH` - изменить текущий каталог
  2. `ls [PATH]` - вывести список всех файлов (включая скрытые) из указанного каталога, либо из текущего каталога, если он не указан
  3. `mkdir PATH` - создать каталог; в качестве имени может быть указано либо абсолютный, либо относительный путь
  4. `rm [-r] PATH` - удалить файл либо, при указании флага `-r` - удалить каталог рекурсивно
  5. `stat PATH` - отобразить информацию о файле: размер, тип UNIX-файла, количество жестких ссылок и права доступа в восьмеричном виде
  

## Функциональные требования на оценку "отлично"

Дополнительно к критериям на оценку "хорошо", реализованы команды монтирования, которые позволяют подключать
содержимое образов дисков:
 1. `mount IMAGE_PATH MOUNT_DIR_PATH` - подключить образ из файла к каталогу
 2. `umount MOUNT_DIR_PATH` - отключить образ от каталога

Формат внутреннего представления образов дисков не регламентирован, и может быть реализован на ваше усмотрение. Требования к формату образов: 
  1. Иметь возможность хранить файлы следующих типов: регулярные файлы (включая бинарные) и символические ссылки
  2. Сохранять атрибуты файлов (владелец, права доступа и пр.) 
  3. После отмотнтирования образа и повторного его монтирования (в том числе при перезапуске Docker-образа) содержимое файлов в образе должно сохраняться.
